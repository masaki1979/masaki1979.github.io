Privacy Policy

Personal Video Scheduler · Effective date: October 4, 2026 (first published October 3, 2026)

Personal Video Scheduler uses YouTube API Services. By using this app, you are also subject to the Google Privacy Policy (http://www.google.com/policies/privacy).

Personal Video Scheduler is an independent personal tool and is not affiliated with, endorsed by, or sponsored by Google or YouTube.

1. About this policy

This Privacy Policy explains how Personal Video Scheduler (the "App") accesses, uses, stores, and shares information. The App is operated by masaki1979 (the "Operator"). It is a personal tool that runs on the Operator's own computer and is used by the Operator to schedule uploads of the Operator's own videos to YouTube channels that the Operator owns or manages. The App is not offered to the public.

2. Use of YouTube API Services

The App uses YouTube API Services to upload videos, set thumbnails, and read information about videos on the authorized channels. Information obtained through YouTube API Services is also handled by Google in accordance with the Google Privacy Policy.

3. Information the App accesses

  • OAuth tokens: the access token and refresh token that Google issues when the App is authorized, the permissions (scopes) that were granted, and the token's expiry time. The App uses them only to call YouTube API Services for the authorized channel.
  • Information about the authorized channel: the channel ID, channel name, channel handle, and the ID of the channel's list of uploaded videos. These are used only to tell the Operator's channels apart, to confirm that a video is uploaded to the intended channel, and to find the channel's videos.
  • Information about the channel's videos: for videos that are already uploaded, scheduled, or published: video ID, title, publish date and time (or upload date and time for videos that are not yet public), scheduled publish time, privacy status, and video length (used to tell Shorts from long-form videos).
  • Status details: for videos uploaded by the App, and for up to 10 videos found during the duplicate check that may be an earlier attempt of the same upload (videos with the same title, and videos that were published or uploaded after that attempt started — from 10 minutes before it — and are not recorded by the App), the App also reads the upload and processing status and the reason for a failure or rejection if any. For videos uploaded by the App, it also reads the made-for-kids, altered or synthetic content, and paid promotion declarations, to confirm that the settings were applied. When the Operator asks the App to record a video that the Operator found in YouTube Studio as the result of an earlier attempt, the App reads that video's channel ID, title, publish date, and status (including the reason for a failure or rejection, if any) to confirm it, and records it only if it belongs to the intended channel, is not already recorded, and did not fail.
  • Videos and metadata the Operator uploads: the video file, thumbnail image, title, description, tags, the privacy setting chosen by the Operator (private, unlisted, or public; private by default — the schedule command always adds a scheduled publish time, and the post command adds one when the Operator gives it), the scheduled publish time, and default values set by the Operator (category, language, made-for-kids declaration, altered or synthetic content declaration, and paid promotion declaration).
  • Upload session information: the temporary upload address that YouTube returns for an upload, and the progress information YouTube sends back during the upload. These are used only to resume an interrupted upload.

Although the youtube.readonly permission would allow reading other channel information, the App asks YouTube only for the information listed above, as far as the API allows. When YouTube's responses include more items than the App uses (for example, all status items in its response to an upload, or the thumbnail addresses in its response to setting a thumbnail), the App uses and stores only the items listed above. The App does not access comments, subscribers, analytics, payment information, contacts, email, or any other Google service.

4. How the information is used

The information is used only to:

  • upload and schedule videos (including setting thumbnails and video settings), and resume interrupted uploads;
  • confirm that an upload finished and that the settings were applied;
  • find a free date and time that is not already used by a scheduled or published video, and avoid uploading the same video twice.

It is not used for any other purpose, such as advertising, profiling, or analytics.

5. Where the information is stored

All information is stored only on the device where the App runs (the Operator's own computer), inside the Operator's user folder. The App has no server, and the Operator does not store the information in any cloud service. The App stores:

  • Token files (one per channel): the refresh token, the granted permissions, the date of authorization, the client ID of the App that issued the token and the name of the App's client settings file, the name the Operator gave to the channel in the App, the channel ID, channel name and handle, the date this channel information was last checked (or a short note that it was deleted), the version of the Privacy Policy and Terms that was agreed to and the date and time of the agreement, and, if access stops working or is revoked, the date the App noticed this. If a revocation cannot be completed at once, a small marker file with the same dates is kept until the deletion is finished.
  • Posting log: for each video upload by the App, including uploads that failed or were interrupted, the Operator's own settings (such as the title and which title option was used, the location of the description file if one was specified, the privacy setting, and the scheduled publish time) and the progress of the upload, and, from the API, the video ID and URL, the channel name and ID, the upload status, privacy status, scheduled publish time and processing status as registered on YouTube, and the date this information was last checked. The posting log file is also read and written, on the same computer, by the posting tool that the Operator used before this App. Information that this App obtained from YouTube API Services is not sent anywhere; the earlier tool sends only its own Upload-Post request information to Upload-Post.
  • Test upload log: the same kind of information for very short test uploads, which are always private, together with the location of the test video file on the computer.
  • Temporary upload session files: for an upload in progress, the upload address, the name of the video folder, the content ID the App uses to recognize the same upload, whether it is a Short, the channel name in the App, the file name, size and modification time, and the creation time. A session file is deleted when the upload is completed, when access is revoked, or 7 days after it was created. There are two exceptions: if the posting log is in use by another task when the file is due to be deleted, the file is kept until the next opportunity, for at most 10 days; and if YouTube has confirmed that the upload finished but the posting log could not be updated, the file is kept until the posting log is updated, for at most 27 days.
  • Refresh log: a log of each daily automatic refresh (the date, the result, counts, and the messages shown, which name the App's channel names, video folders and files). Video IDs and other information obtained from YouTube API Services are not written to it, and lines older than 30 days are deleted.

Lists of videos read to find free dates, to prevent duplicate uploads, or to confirm an upload are only shown on the screen and are not stored. Error messages returned by the API are not stored. The App does not place, read, or recognize cookies or similar technologies.

6. Sharing

  • The information is not shared with, sold to, or rented to any third party.
  • The App sends information obtained from YouTube API Services only to Google / YouTube, for the purposes described above.
  • During a transition period, for the Operator's main channel only, the App also reads the list of posts the Operator has scheduled with Upload-Post, a posting service that the Operator used before this App, using the Operator's own Upload-Post account and API key. This is done only to avoid scheduling two videos on the same day, and the list is not stored. Only this read request is sent to Upload-Post; no information obtained from YouTube API Services is sent to it.
  • The App does not allow any third party to serve content or advertisements through it, or to collect information from its users. The App does not use advertising, analytics, tracking, or cookies.

7. Retention of API data

  • Data obtained from YouTube API Services that the App stores (the API information in the posting log and the test upload log, and the channel information in the token files) is refreshed with current data from the API once it is more than 19 days old, so that it is refreshed within 20 days. Information that cannot be refreshed is deleted after 27 days, before it becomes 30 days old. This is done whenever the App is used to check, plan, post, schedule, or check the status of an upload, and by an automatic refresh that runs once a day on the Operator's computer.
  • If a video can no longer be found, the App checks it again at the next opportunity and, if it is still not found, deletes its API information from the posting log. For uploads that were interrupted, the API information is deleted after 27 days, while the Operator's own record that an upload was attempted is kept so that the same video is not uploaded twice.
  • If access is revoked from your Google Account settings, the App deletes the refresh token that no longer works as soon as it notices this, and deletes the stored API data for that channel 22 days after noticing it (within 30 days in any case).
  • If this Privacy Policy or the Terms are updated, the App does not read information from YouTube for a channel until the new version has been agreed to (deletion under the rules above continues).
  • OAuth tokens are kept only as long as they are needed to keep the App authorized.

8. How to revoke access

You can revoke the App's access to your Google Account at any time:

  • Google Account, "Third-party apps & services": https://myaccount.google.com/connections
  • Google security settings page: https://security.google.com/settings/security/permissions

The App also has its own command to revoke access. When it is used and a usable token is stored together with a record of the App client that issued it, the App immediately asks Google to revoke the access, then deletes the API data stored for that channel, the upload session files, and the token file. If Google accepts the revocation, the same is done for any other name the Operator saved for the same channel with the same authorization (the same App client); for other names, and when Google does not accept it, the App tells the Operator to revoke each name. If no such token is stored (including a token saved by an older version of the App without that record), the App deletes the stored data and asks you to remove the access from your Google Account settings (links above). If any deletion cannot be finished at once, the App finishes it the next time it runs, and in any case within 7 days.

After access is revoked, the App can no longer read or upload anything for that account.

Deleting data stored by the App does not affect any data stored by YouTube. Videos uploaded with the App stay on YouTube. To delete them, use YouTube Studio or another app that supports deleting videos.

9. How to request deletion

You can ask for your stored information (for example, tokens and posting log entries related to your channel) to be deleted by sending an email to masaki.1979ai@gmail.com. The Operator will delete it within 7 days of receiving the request and will reply to confirm. Deleting data stored by the App does not delete videos or other data stored by YouTube; to delete those, use YouTube Studio.

10. Security

Tokens and other stored information are kept only on the Operator's computer, inside the Operator's user folder, and are not published. Google tokens are sent only to Google, and the Operator's Upload-Post API key is sent only to Upload-Post.

1. このポリシーについて

このプライバシーポリシーは、Personal Video Scheduler（以下「本アプリ」）が情報をどのように読み取り、使い、保存し、共有するかを説明するものです。本アプリは masaki1979（以下「運営者」）が運営しています。本アプリは運営者のパソコンの中で動く個人用のツールで、運営者が自分で作った動画を、自分が所有・管理する YouTube チャンネルに予約投稿するために使います。一般には公開していません。

2. YouTube API Services の利用

本アプリは YouTube API Services を使って、動画のアップロード、サムネイルの設定、許可されたチャンネルの動画の情報の読み取りを行います。YouTube API Services を通じて扱われる情報は、Google プライバシーポリシーにしたがって Google によっても取り扱われます。

3. 本アプリが読み取る情報

  • OAuth のトークン：本アプリを許可したときに Google が発行するアクセストークンと更新用トークン、許可された権限（スコープ）、トークンの有効期限。許可されたチャンネルについて YouTube API Services を呼び出すためだけに使います。
  • 許可されたチャンネルの情報：チャンネル ID、チャンネル名、ハンドル、そのチャンネルのアップロード動画の一覧の ID。運営者のチャンネルを見分け、意図したチャンネルにアップロードすることを確かめ、チャンネルの動画を探すためだけに使います。
  • チャンネルの動画の情報：アップロード済み・予約済み・公開済みの動画の動画 ID、タイトル、公開日時（まだ公開されていない動画はアップロード日時）、公開予定時刻、公開状態、動画の長さ（ショートと通常の動画を見分けるため）。
  • 状態の詳しい情報：本アプリでアップロードした動画と、二重アップロードの確認で見つかった「同じアップロードの前回の試みかもしれない動画」（タイトルが同じもの、その試みを始めた時刻（の10分前）より後に公開またはアップロードされ本アプリの記録に無いもの。10本まで）については、アップロードと処理の状況、失敗や却下の理由（ある場合）も読みます。本アプリでアップロードした動画については、子ども向けの申告・改変または合成コンテンツの申告・有料プロモーションの申告も読み、設定が反映されたことを確かめます。運営者が YouTube Studio で見つけた「前回の試みでできた動画」を記録に取り込むよう指示したときは、その動画のチャンネル ID、タイトル、公開日時、状態（失敗や却下の理由がある場合はそれも）を読んで確かめ、意図したチャンネルの動画で、まだ記録に無く、失敗していないときだけ記録します。
  • 運営者がアップロードする動画とメタデータ：動画ファイル、サムネイル画像、タイトル、説明、タグ、運営者が選んだ公開設定（非公開・限定公開・公開。既定は非公開。予約のコマンドはいつも公開予定時刻を付け、投稿のコマンドは運営者が指定したときに付けます）、公開予定時刻、運営者が決めた既定値（カテゴリー、言語、子ども向けの申告、改変または合成コンテンツの申告、有料プロモーションの申告）。
  • アップロードのセッションの情報：アップロードのときに YouTube が返す一時的なアップロード先と、アップロード中に YouTube が返す進み具合の情報。途中で止まったアップロードを続きから送るためだけに使います。

youtube.readonly の許可ではほかのチャンネル情報も読めますが、本アプリは、API で指定できる範囲で、上に挙げた情報だけを YouTube に求めます。YouTube の応答に本アプリが使う以上の項目が含まれる場合（たとえばアップロードへの応答の状態の全項目や、サムネイルの設定への応答のサムネイルのアドレス）も、本アプリが使い、保存するのは上に挙げた項目だけです。コメント、登録者、アナリティクス、支払い情報、連絡先、メール、そのほかの Google のサービスにはアクセスしません。

4. 情報の使い道

情報は次の目的だけに使います。

  • 動画のアップロードと予約公開（サムネイルや動画の設定を含む）、途中で止まったアップロードの再開
  • アップロードが終わったことと、設定が反映されたことの確認
  • 予約済み・公開済みの動画と重ならない、空いている日時の判定と、同じ動画の二重アップロードの防止

広告、プロファイリング、解析など、ほかの目的には使いません。

5. 情報の保存場所

情報はすべて、本アプリが動く端末（運営者のパソコン）の中、運営者のユーザーフォルダ内だけに保存します。本アプリにはサーバーがなく、運営者がクラウドサービスに保存することもありません。保存するものは次のとおりです。

  • テスト送信の記録：ごく短いテスト動画のアップロード（いつも非公開）についての、投稿記録と同じ種類の情報と、パソコンの中のテスト動画の場所。

空いている日時の判定、二重アップロードの防止、アップロードの確認のために読んだ動画の一覧は、画面に表示するだけで保存しません。API が返したエラーの文も保存しません。本アプリは Cookie やそれに似た技術を置いたり、読んだり、利用したりしません。

6. 共有

  • 情報を第三者に共有・販売・貸与することはありません。

  • 移行期間中は、運営者のメインのチャンネルについてだけ、本アプリの前に運営者が使っていた投稿サービス Upload-Post から、運営者が予約した投稿の一覧を、運営者自身の Upload-Post のアカウントと API キーで読み取ります。同じ日に2本の動画を予約しないためだけに行い、一覧は保存しません。Upload-Post に送るのはこの読み取りの依頼だけで、YouTube API Services から得た情報は送りません。

7. API から得たデータの保存期間

  • 本アプリが保存する YouTube API Services から得たデータ（投稿記録とテスト送信の記録の中の API の情報、トークンのファイルの中のチャンネル情報）は、19 日を過ぎたら API から最新のデータを取り直し、20 日以内に取り直します。取り直せない情報は、30 日になる前（27 日を過ぎたとき）に削除します。これは、本アプリで確認・計画・投稿・予約・状況の確認をするたびと、運営者のパソコンで 1 日 1 回動く自動の取り直しで行います。
  • 動画が見つからなくなった場合は、次の機会にもう一度確かめ、やはり見つからなければ、その動画の API の情報を投稿記録から削除します。途中で止まったアップロードについては、API の情報を 27 日を過ぎたときに削除します。ただし、同じ動画を2回アップロードしないように、アップロードを試みたという運営者自身の記録は残します。
  • Google アカウントの設定から許可が取り消された場合、本アプリはそれに気づいた時点で使えなくなった更新用トークンを削除し、そのチャンネルについて保存している API のデータを、気づいてから 22 日たったときに（どの場合も 30 日以内に）削除します。
  • このプライバシーポリシーまたは利用規約が更新された場合、新しい版に同意するまで、本アプリはそのチャンネルについて YouTube から情報を読みません（上の決まりによる削除は続けます）。
  • OAuth のトークンは、本アプリの許可を保つために必要な間だけ保存します。

8. 許可の取り消し方

本アプリへの Google アカウントの許可は、次のページからいつでも取り消せます。

  • Google アカウントの「サードパーティ製のアプリとサービス」：https://myaccount.google.com/connections
  • Google のセキュリティ設定のページ：https://security.google.com/settings/security/permissions

本アプリにも許可を取り消すコマンドがあります。使えるトークンが、それを発行した本アプリのクライアントの記録と一緒に保存されているときにこれを使うと、本アプリはすぐに Google に許可の取り消しを依頼し、そのチャンネルについて保存している API のデータ、アップロードのセッションのファイル、トークンのファイルを削除します。Google が取り消しを受け付けた場合は、運営者が同じチャンネルを同じ許可（同じクライアント）で別の名前でも保存していれば、その名前の分も同じように削除します。それ以外の名前の分と、Google が受け付けなかった場合は、名前ごとに取り消すよう運営者に案内します。そのようなトークンが保存されていないとき（その記録の無い、本アプリの古い版で保存したトークンを含みます）は、保存しているデータを削除し、Google アカウントの設定（上のリンク）から許可を外すよう案内します。削除の一部をその場で終えられなかった場合は、次に本アプリが動いたときに終え、どの場合も 7 日以内に終えます。

許可を取り消すと、本アプリはそのアカウントについて読み取りもアップロードもできなくなります。
